## 進捗ログ

### 2026-10-08
**◆対応者：Claude Sonnet 5**

- 着手前調査で、本バックログに影響するバックエンド側・共通基盤側の2件の問題を発見し、`hojou`のレビュー工程ルールに従って対応した（詳細は`実装（認証・ユーザー管理フロントエンド）_フロントエンド実装.md`の影響資材、および参照先の各引継書を参照）。
    - Bug #1：`GET /users/me`の依存性注入誤り（設計・実装両方の仕様誤り）。
    - Bug #2：`ProtectedRoute`・`AdminRoute`に初回パスワード変更未完了時のガードが欠落（実装漏れ）。
- `frontend/src/contexts/AuthContext.tsx`に`changePassword(currentPassword, newPassword)`を追加した（仕様追加。バグ修正ではないためレビュー指摘表は作成せず、本書にのみ記録する）。
    - `PATCH /users/me/password`を呼び出し、発行された新しいアクセストークンを保存した上で`GET /users/me`を呼び出し、最新のユーザー情報を返却する。
    - `login`と`changePassword`で共通する「トークン保存→自分の情報取得→状態反映」処理を、非公開ヘルパー`applyAccessToken`に抽出して共通化した。
- `frontend/src/pages/LoginPage.tsx`（新規）：ユーザーID・パスワードを入力して`AuthContext.login`を呼び出す。ログイン成功後、`password_change_required_flag`が`true`であれば`/change-password`へ、そうでなければ`/`へ遷移する。
- `frontend/src/pages/ChangePasswordPage.tsx`（新規）：現在のパスワード・新しいパスワードを入力して`AuthContext.changePassword`を呼び出す。成功後は`/`へ遷移する（初回ログイン時の変更もこの画面を利用する想定）。
- `frontend/src/pages/UserManagementPage.tsx`（新規）：ユーザー一覧表示（`GET /users`）、新規登録（`POST /users`）、編集（`PUT /users/{user_id}`）、無効化・再有効化（`PATCH /users/{user_id}/deactivate` / `.../activate`）、パスワード初期化（`PATCH /users/{user_id}/reset-password`）を1画面に実装した。一覧・登録・編集・パスワード初期化をパネル切り替え（`list`/`create`/`edit`/`reset-password`）で表示する構成とした。
    - 初回読み込み失敗時に再試行できるよう、エラー表示とともに再試行ボタンを表示する（`React_実装_チェックリスト.md`「非同期状態管理」に基づく対応）。
- `frontend/src/App.tsx`：`/login`・`/change-password`（`ProtectedRoute`）・`/users`（`AdminRoute`）のルートを追加した。いずれも`Layout`でラップしてヘッダーを表示する。
- `frontend/src/components/Header.tsx`：管理者ユーザーの場合に「ユーザー管理」への遷移リンク（`/users`）を表示するよう追加した。
- `npm run lint`（既存の警告1件のみ。新規コードに起因する指摘なし）・`npm run typecheck`・`npm run build`・`npx prettier --write`（新規・修正ファイルのみ対象。リポジトリ全体には`git`のCRLFチェックアウト設定由来の整形差分が既存するため、本バックログでは触れていない）で問題がないことを確認した。
- Vitest + React Testing Libraryによる一時的な動作確認（テストファイルは確認後に削除）：
    - ログイン成功時、初回パスワード変更要否に応じて`/`または`/change-password`へ遷移すること、認証失敗時にエラーメッセージが表示されることを確認した。
    - ログイン済み状態（`localStorage`にトークン保存済み）からのパスワード変更が成功し、`/`へ遷移することを確認した。
    - 管理者ユーザーでのユーザー一覧表示、新規登録後に一覧が更新されることを確認した。
