- `frontend/src/types/common.ts`：`UserGetResponse`（`設計書/スキーマ（schemas）/ユーザー操作_v0.2.0.md`のUserGetResponse。`UserBase`継承分の`name`・`department`を含む）・`TokenResponse`（`設計書/スキーマ（schemas）/認証・認可_v0.3.0.md`）・`Role`型を定義した。
- `frontend/src/api/client.ts`：APIクライアント基盤を実装した。
    - ベースURL：`import.meta.env.VITE_API_BASE_URL`（既存の`.env.example`・`docker-compose.yml`の設定にそのまま従う。開発時はバックエンドへ直接アクセス、Nginx配信時は`frontend/nginx.conf`の`/api/`中継を利用する想定）。
    - `setAccessToken`／`setUnauthorizedHandler`：認証トークンの設定、401エラー時共通処理の登録。トークン自体の永続化（localStorage）は呼び出し側（`AuthContext`）の責務とし、本モジュールはリクエスト時に使うメモリ上の値のみを保持する。
    - `apiGet`／`apiPost`／`apiPatch`／`apiPut`／`apiDelete`：JSON形式の共通リクエスト関数。
    - `postForm`：`application/x-www-form-urlencoded`形式での共通リクエスト関数（`POST /token`がOAuth2PasswordRequestFormを受け取るため）。
    - レスポンスが401の場合は登録済みの401エラー時共通処理を呼び出し、2xx以外の場合は`ApiError`（ステータスコード・エラー内容を保持）を発生させる。
- `frontend/src/contexts/AuthContext.tsx`：`AuthProvider`（ログイン状態のProvider）・`useAuth`（参照用フック）を実装した。
    - 初回マウント時、`localStorage`に保存済みの認証トークンがあれば`client.ts`に設定した上で`GET /users/me`を呼び出し、ログイン状態を復元する（失敗時はログイン状態をクリア）。
    - `login(userId, password)`：`POST /token`（フォームエンコード）でトークン発行後、`localStorage`へトークンを保存し、`GET /users/me`でユーザー情報を取得する。
    - `logout()`：`POST /logout`を呼び出し、成否に関わらずログイン状態（トークン・ユーザー情報）をクリアする。
    - `client.ts`の401エラー時共通処理として、ログイン状態のクリア処理を登録する（トークン失効時に自動的にログアウト状態へ遷移する）。
    - ログイン画面（S01）自体は実装（認証・ユーザー管理）バックログで作成するが、ルーティングガードから認証状態を参照できる必要があるため、本タスクで仕組み自体を用意した。
- `frontend/src/components/`：共通コンポーネントを実装した。
    - `Header.tsx`：アプリ名、ログイン中ユーザー氏名、ログアウト操作を表示する。
    - `Layout.tsx`：`Header`と画面本体を組み合わせる共通の画面枠。画面間の遷移リンク（ナビゲーション）は、各画面のURLパスがまだ設計書上定義されていない（`要件定義書/画面一覧_v1.0.0.md`は画面名・役割のみを定義し、ルーティングパスは未定義）ため、各画面の実装バックログでヘッダー内に追記する前提とした。
    - `LoadingIndicator.tsx`：読み込み中表示。
    - `ErrorMessage.tsx`：エラー内容表示。
    - `ProtectedRoute.tsx`：未ログイン時に`/login`へリダイレクトする認証必須ルートガード。
    - `AdminRoute.tsx`：未ログイン時に`/login`へ、管理者ロールでない場合は`/`へリダイレクトする管理者限定ルートガード（サーバー側の`auth.require_admin`による認可は別途必須であり、本ガードはクライアント側のUX上の制御に留まる）。
- `frontend/src/App.tsx`：`AuthProvider`・`BrowserRouter`・`Routes`の骨格のみを実装した。画面単位のルート（S01〜S11）は未定義（キャッチオール`*`のみ）とし、各対応する機能群の実装バックログで本ファイルへ追記する前提とした。
- `frontend/src/main.tsx`：Reactアプリケーションをルート要素へマウントするエントリーポイントを実装した。
- `frontend/src/vite-env.d.ts`：`import.meta.env.VITE_API_BASE_URL`の型定義を追加した（当初の修正対象資材に記載がなかったため、タスク詳細ファイルに追記した）。
- `npm run lint`（警告1件：`AuthContext.tsx`が`react-refresh/only-export-components`の対象。コンポーネント（`AuthProvider`）とフック（`useAuth`）を同一ファイルからエクスポートしているための警告であり、認証コンテキストの一般的な実装パターンのため許容する）・`npm run typecheck`・`npm run build`（`VITE_API_BASE_URL`指定）・`npx prettier --check`で問題がないことを確認した。
