## 目的・背景

「結合テスト（認証・ユーザー管理）」バックログ（Issue #45、優先度22）の対象エンドポイントに対する結合テスト仕様書を作成する。F01・F02・F16のうち、直前の「結合テスト（共通）」バックログ（Issue #43、PR #44）で既にカバー済みの`POST /token`（ログイン）・`POST /logout`（ログアウト）を除く残り9エンドポイントが本バックログの対象。

## 進捗ログ

### 2026-10-12
**◆対応者：Claude Sonnet 5**

- 設計書確認：`設計書/エンドポイント_v0.2.0.md`で全エンドポイントを確認し、F01・F02・F16に対応する11エンドポイントのうち、結合テスト（共通）でカバー済みの2件を除く9エンドポイントを対象として確定した。
    - `GET /users/me`（自分の情報取得）・`PATCH /users/me/password`（パスワード変更）・`GET /users`（ユーザー一覧取得）・`POST /users`（ユーザー登録）・`GET /users/{user_id}`（ユーザー詳細取得）・`PUT /users/{user_id}`（ユーザー編集）・`PATCH /users/{user_id}/deactivate`（ユーザー無効化）・`PATCH /users/{user_id}/activate`（ユーザー再有効化）・`PATCH /users/{user_id}/reset-password`（パスワード初期化）
- `backend/app/main.py`・`backend/app/auth.py`・`backend/app/services.py`・`backend/app/crud.py`・`backend/app/schemas.py`・`backend/app/models.py`を実装コードから直接確認し（推測で記載しない：IT-CHK-07）、全条件分岐（401・403・404・409・400・422・200・201）を洗い出した。
    - admin系9エンドポイント中8件が`_: User = Depends(auth.require_password_changed)`を`current_admin: User = Depends(auth.require_admin)`より先に宣言しているため、初回パスワード変更未了の管理者は403（パスワード変更要求）で止まり、権限チェック（403管理者権限）より先に評価されることを確認した。このため、管理者権限系の403テストでは、テスト対象の管理者ユーザーを事前にパスワード変更済みにする必要がある（仕様書の前提条件に明記した）。
    - `crud.get_user_by_user_id`が有効フラグによる絞り込みを行わないため、無効化済みユーザーのユーザーIDは`register_user`の重複確認で引き続き使用中と判定され、再登録時も409になることを確認し、ユーザー登録の仕様書にケースとして追加した。
    - `activate_user`はトークン世代を変更せず維持する（`deactivate_user`で進めた世代をそのまま使う）設計であることを確認し、ユーザー再有効化の仕様書に「トークン世代が変更されないこと」の検証観点として追加した。
- 9エンドポイント・計48ケースの結合テスト仕様書を作成し、`test_specification/integration_test_specification/認証・ユーザー管理/`に格納した（新規作成のため`_v0.1.0.md`で作成）。
